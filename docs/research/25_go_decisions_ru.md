# 25 задач для принятия и проверки решений FaceX

Реализация на Go использует стандартную библиотеку. Команды ниже запускаются из go/facex. Новые методы доступны отдельно от обычного Identify. Подбор параметров, приоритет ручной проверки и статистический аудит выполняются на явно переданных данных.

| № | Задача | Метод и результат |
|---|---|---|
| 1 | Суммировать веса всех допустимых назначений лиц с возможностью пропуска | InferAssignments возвращает логарифм нормирующей суммы. Динамика по маске уже занятых кандидатов использует log-sum-exp. |
| 2 | Узнать модельную вероятность каждого ID и пропуска для каждой строки | Прямой и обратный проход по маскам суммируют массы всех совместимых решений. |
| 3 | Получить распределение числа совпадений в кадре | Массы финальных масок складываются по числу занятых столбцов. |
| 4 | Измерить неопределённость всего кадра с учётом конкуренции за ID | Энтропия совместного распределения равна log Z минус ожидаемый суммарный лог-вес. |
| 5 | Минимизировать ожидаемое число неверных решений по строкам | Вторая динамика максимизирует сумму маргинальных вероятностей при уникальности ID. Пропуск тоже является решением. |
| 6 | Найти лучшую последовательность состояний трека при штрафе за смену | SolveTrackPath восстанавливает оптимальный путь по указателям предшественников. |
| 7 | Оценить цену вынужденной смены решения в конкретном кадре | Прямая и обратная полезности дают лучший путь, в котором этот кадр имеет другое состояние. Нулевая потеря означает равносильную альтернативу. |
| 8 | Построить оптимум для каждого точного числа переключений | Динамика по времени, числу переключений и состоянию сохраняет двух лучших разных предшественников. |
| 9 | Найти минимальный штраф, при котором оптимален постоянный ID | Сравниваем лучший постоянный путь со всеми точками кривой «число смен — полезность». При граничном штрафе возможна ничья. |
| 10 | Найти диапазон штрафов для каждого возможного числа переключений | Пересечение линейных неравенств показывает также числа смен, которые нельзя сделать оптимальными ни одним штрафом. |
| 11 | Разбить видеотрек на k непрерывных сегментов с минимумом суммарного искажения | SegmentDirections использует стоимость отрезка 2(L − ‖Σu‖) для единичных векторов, затем восстанавливает оптимальные границы. |
| 12 | Минимизировать искажение самого плохого сегмента | Отдельный minimax-переход учитывает худшую локальную ошибку. |
| 13 | Выбрать количество сегментов с учётом цены каждой новой границы | Минимизируем оптимальное суммарное искажение плюс штраф за k−1 границ. |
| 14 | Найти наименьшее число сегментов при локальном ограничении искажения | Проверяем minimax-кривую; 0 означает, что ни одно разрешённое число сегментов не подходит. |
| 15 | Найти стоимость второго, отличного разбиения при фиксированном k | Два лучших различных пути на ячейку сохраняют вторую стоимость, включая равную первой. При единственном разбиении стоимость альтернативы бесконечна. |
| 16 | Построить полный обмен между объёмом проверки, снятыми ошибками и задержанными правильными ID | AnalyzeReview сортирует принятые решения и обрабатывает все равные приоритеты одним блоком. Один элемент — один размеченный визит. |
| 17 | Снять максимум ошибок при лимите задержанных правильных решений | Выбираем достижимый детерминированный порог по полной кривой. |
| 18 | Найти наименьший объём ручной проверки при допустимом числе оставшихся ошибок | Первый достижимый порог, удовлетворяющий целевому остатку. |
| 19 | Найти порог с минимальной суммарной ценой проверки и оставшихся ошибок | Перебираем все пороги, включая отсутствие проверки. |
| 20 | Сравнить приоритеты проверки сразу по всем уровням покрытия | Дискретная площадь риск–покрытие усредняет ожидаемую долю ошибок для каждого непустого размера оставшейся выборки. Внутри равного приоритета порядок равновероятен. |
| 21 | Оценить интервал частоты ошибок по числу визитов | VisitErrorInterval обращает биномиальные хвосты для центрального интервала Клоппера–Пирсона. |
| 22 | Проверить изменение частоты ошибок двух правил на одних и тех же визитах | AuditPairedVisits вычисляет двусторонний точный критерий Мак-Немара по числу исправленных и внесённых ошибок. |
| 23 | Ограничить абсолютное снижение риска ошибок в парном эксперименте | Одновременные биномиальные интервалы для двух направлений расхождения по поправке Бонферрони дают консервативный интервал разности. |
| 24 | Определить объём независимой проверки при нуле наблюдаемых ошибок | ZeroErrorVisits обращает (1−p)^n для односторонней доверительной границы. |
| 25 | Оценить отношение вероятностей «стало лучше / стало хуже» | Условный биномиальный интервал по расходящимся парам переводится в интервал шансов. При отсутствии расхождений интервал от 0 до бесконечности. |

## Границы применимости

Лог-веса назначения задаются относительно пропуска. Для вероятностной интерпретации на камерах их необходимо калибровать отдельно. Расчёт точный в рамках заданной конечной модели с обычным округлением float64, экспоненциален по числу кандидатов и ограничен 16 кандидатами и 2²⁰ ячейками на таблицу. Трек допускает до 256 кадров и 64 состояний. Добавьте отдельный столбец для неизвестного, если это предусмотрено моделью трека. Сегментация допускает до 256 кадров, сравнивает все разбиения через динамическое программирование и занимает O(T²d + KT²) времени. Нулевые векторы для неё недопустимы.

Для аудита двух правил нужны одни и те же размеченные визиты, заранее зафиксированные правила и независимость между визитами. Кадры одного визита нельзя считать отдельными независимыми наблюдениями. Интервалы по визитам поддерживают от 1 до 1 000 000 наблюдений. Детерминированное снятие ID означает передачу на проверку; исход работы оператора моделируется отдельно.

## Воспроизведение

- `go test -race -run '^TestDecision' ./...` — независимые проверки по малым задачам и граничным случаям.
- `FACEX_GALLERY_SCALE=1 go test -v -run '^TestDecisionWorkloads$'` — замеры на фиксированных синтетических входах.
- В CI TestDecisionModelReplay использует прежние векторы EdgeFace XS: 10 исходных людей в регистрации, 5 оставлены неизвестными. Первый по сходству ID служит базовой линией. Фиксированный порог отрыва 0,1 передаёт спорный ответ на перепроверку. Это стенд на фотографиях, а не разметка реальных посещений.

Справка по условному парному тесту и интервалу шансов: [R exact2x2](https://search.r-project.org/CRAN/refmans/exact2x2/html/exact2x2.html).

# 15 задач для Go SDK FaceX

Все функции находятся в пакете go/facex. Вычисления регистрации и верификации используют float64. Сопоставление принимает целочисленную матрицу полезностей в миллионных долях. Пропуск имеет нулевую полезность. Запрещённое ребро отмечают значением ForbiddenAssociation. Перед сопоставлением по косинусу вызывающая сторона выбирает порог допустимости и переводит оценки в эти единицы.

| № | Задача | Решение и результат |
|---:|---|---|
| 1 | Построить единичный шаблон, минимизирующий взвешенную сумму квадратов хордовых расстояний | FitDirections нормирует взвешенную сумму единичных векторов. При почти полном сокращении направлений Template равен nil. |
| 2 | Найти реальное наблюдение, минимизирующее суммарное взвешенное косинусное расстояние | Максимизируем скалярное произведение наблюдения со взвешенной суммой. Поле Medoid вычисляется за O(nd) для n снимков размерности d. |
| 3 | Найти максимальный поворот шаблона после удаления одного снимка | Префиксные и суффиксные суммы дают все n направлений за O(nd). Угол берётся через atan2. При неопределённом направлении хотя бы в одном исключении LeaveOneOutDefined равен false. |
| 4 | Выбрать один снимок, лучше всего покрывающий худший ракурс | CoverViews(rows, 1) максимизирует наименьший косинус до выбранного наблюдения. Достаточно одного минимума на ракурс. |
| 5 | Найти оптимальную пару эталонных ракурсов | Для порога косинуса строим битовые множества покрытых снимков. Проверяем, покрывает ли их объединение двух множеств, и ищем наибольший достижимый порог среди наблюдаемых значений. |
| 6 | Оценить ROC AUC с одинаковыми оценками | EvaluateVerification обрабатывает группу равных оценок за один переход. Равенство подлинной и посторонней пары получает половинный вес. |
| 7 | Измерить качество только до заданной частоты ложных совпадений | Точно отсекаем последний отрезок ломаной ROC в точке maxFAR и считаем ненормированную площадь PartialAUC. |
| 8 | Найти частоту ошибок при равенстве FAR и FRR | Ищем пересечение на интерполированной ROC. EER может лежать между двумя достижимыми целочисленными режимами. |
| 9 | Найти рабочий порог с минимальной ценой ошибок | Перебираем все достижимые пороги и минимизируем prior-weighted costMiss × FRR + costFalse × FAR. Включён вариант отклонения всех пар. |
| 10 | Принять максимум подлинных пар при жёстком бюджете ложных совпадений | Выбираем детерминированную рабочую точку BudgetPoint. Группа равных оценок принимается целиком. |
| 11 | Сопоставить лица и кандидатов с максимальной суммарной полезностью, разрешая пропуски | AnalyzeAssociations возвращает Best. Каждый кандидат может принадлежать только одному лицу. |
| 12 | Найти максимум допустимых соответствий и лучшую полезность при этом количестве | MostMatches использует лексикографический приоритет числа совпадений, затем полезности. |
| 13 | Измерить, насколько неоднозначно каждое отдельное назначение с учётом перестановок остальных лиц | AssociationRegrets вычисляет минимальную потерю при принудительной смене решения каждой строки. Для равносильной альтернативы потеря нулевая, при отсутствии альтернативы возвращается -1. |
| 14 | Обеспечить наилучшую оценку самого слабого совпадения для заданного числа лиц | AssociationBottleneck ищет максимальный порог, при котором существуют k независимых рёбер. Проверка выполнимости использует увеличивающие пути. |
| 15 | Получить точный оптимум для каждого достижимого числа соответствий | ByCount хранит полную кривую «число назначений → максимальная полезность» и сами назначения. Каждый следующий поток может пересматривать уже выбранные рёбра. |

Для задач 11, 12 и 15 путь минимальной стоимости в остаточной сети переводит оптимальное k-сопоставление в оптимальное (k+1)-сопоставление. Для задачи 13 добавляем каждому лицу личный столбец пропуска. Вершины графа соответствуют столбцам. Ребро из занятого столбца в другой стоит разницу между прежней и новой полезностью его владельца. Вспомогательная вершина замыкает пути, меняющие набор занятых столбцов. Принудительная смена назначения требует цикла через другое первое ребро. Стоимость ребра плюс кратчайший обратный путь даёт искомую потерю. Отрицательный цикл противоречил бы оптимальности исходного назначения.

Верификация выполняет одну сортировку за O(n log n) и линейный проход. Точное покрытие двумя эталонами хранит квадратичную матрицу оценок. Вычисление всех потерь альтернативных назначений использует кубическое по числу столбцов и лиц замыкание кратчайших путей. Эти операции предназначены соответственно для набора ракурсов одного человека и ограниченного списка кандидатов кадра.

Проверки включают прямой перебор эталонов, попарную формулу AUC, независимый численный поиск EER и полный перебор допустимых назначений в малых прямоугольных матрицах. Команда из go/facex: `go test -race -run '^TestMath' ./...`. Нагрузочный тест: `FACEX_GALLERY_SCALE=1 go test -v -run '^TestMathWorkloads$'`. CI также собирает матрицу из 15 удержанных векторов модели и проверяет совместную работу трёх частей. Снимки происходят из фикстуры с одной исходной фотографией на человека.

## Измерения полного конвейера

**Nano.** В базовой реализации после первой свёртки выделялся буфер по стороне 55 вместо 56. Для честного сравнения поправка применена к обеим сторонам замера. Повторный замер прошлого ускорения на релизных весах дал 6,2894 → 5,3825, 6,2859 → 5,3587 и 6,3861 → 5,4542 мс. Затем сравнили b21cc3d с новым набором оптимизаций на трёх входах:

| Вход | Предыдущая версия, мс | Новая, мс | Снижение CPU-времени |
|---|---:|---:|---:|
| 1 | 5,4281 | 3,7693 | 30,6% |
| 2 | 5,6697 | 3,8639 | 31,9% |
| 3 | 5,6769 | 4,2115 | 25,8% |

Linux, AMD EPYC 9V74, GCC 14, AVX2/FMA. Один закреплённый поток, CPU-время, прогрев и 9 чередующихся серий по 12 вызовов. Веса facex_nano.onnx релиза facex-nano-1.0, SHA-256 bd0094143bb4c7d04a76dcdad4e332f5985847b921ec4d6678c3fd89aaea3889. Вход 1×3×112×112, выход 1×256. На 15 изображениях проекта максимальная абсолютная разница с ONNX Runtime составила 2,1041×10⁻⁵, минимальный косинус 0,9999999943. Для XS на синтетических весах три времени уменьшились с 45,81–49,56 до 23,47–25,71 мс. На AArch64 выполнен функциональный запуск под QEMU. Замеров на физическом Mac и i5-10400F в этом прогоне нет. Согласованность выходов не измеряет точность идентификации людей.

**YuNet.** Координаты центра равны (ячейка + смещение) × шаг, размеры равны exp(выход) × шаг, оценка равна геометрическому среднему вероятностей cls и obj. На сохранённом входе разница между первой нативной детекцией и декодированными выходами ONNX по 15 числам не превышает 0,00001526. [Реализация OpenCV](https://github.com/opencv/opencv/blob/4.x/modules/objdetect/src/face_detect.cpp)

Пилот WIDER FACE val: 640 из 3226 изображений с фиксированным seed 114, 8909 действительных рамок. RGB и letterbox во всех режимах. Порог оценки 0,5, однозначное сопоставление при IoU ≥ 0,5. «Лишние» означает предсказания без пары среди учтённых рамок. Это локальный протокол, официальный AP easy/medium/hard требует отдельного расчёта.

При 320 из 7903 лиц размером менее 16 пикселей совпали только 13. Из 670 размером 16–32 совпали 248, из 239 размером 32–64 совпали 189, из 97 более крупных совпали 83. Увеличение разрешения повышает полноту и число лишних детекций. Кандидат на следующий опыт — обработка фрагментов высокого разрешения при фиксированном бюджете CPU и сопоставимом числе лишних срабатываний.

Учитывались детекции с уверенностью ≥0,5, видимые пешеходы с visibility ≥0,5, обновлённые в текущем кадре треки и сопоставление по IoU >0,5. Сброс каждые 120 кадров, max_age=5 и min_hits=2. ## Как повторить основные проверки

Из корня репозитория в Linux. Для Python-прогонов понадобятся NumPy, Pillow, SciPy, ONNX и ONNX Runtime. Для сравнения с базовой версией нужна история git с коммитом b21cc3d. Передайте локальные пути к релизной модели Nano, YuNet 2023mar и архивам соответствующих наборов.

```sh
make check
python tests/test_verification_thresholds.py
python tests/bench_mfn_release.py facex_nano.onnx
python tools/export_yunet_weights.py yunet_2023mar.onnx /tmp/yunet.bin
OPENBLAS_NUM_THREADS=1 python tests/verify_yunet.py /tmp/yunet.bin --wider WIDER_val.zip wider_face_split.zip --sizes 160 320 640
OPENBLAS_NUM_THREADS=1 python tests/bench_mot17.py MOT17Labels.zip
```

Итого 13 задач с рабочими изменениями с учётом первого прохода и 12 исследованных гипотез. Веса моделей в этом проходе не менялись.

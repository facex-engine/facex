# Проверка FaceX по визитам на проходную

Один визит одного человека даёт ровно один исход. Первое подтверждённое совпадение фиксирует выданный ID. При завершении визита без совпадения результатом считается отказ. Это воспроизведение правила на размеченных записях. Скрипт не управляет проходной.

### Входные данные

Нужен один локальный файл NPZ, который можно сформировать через `np.savez`. Исходные видеозаписи, фотографии и ФИО для расчёта не нужны.

| Массив | Содержание |
|---|---|
| enrollment | Матрица шаблонов зарегистрированных, N × 512 |
| enrolled_ids | N уникальных кодов людей в порядке строк enrollment |
| visit_ids | Уникальный код каждого фактического визита, в том числе без успешной детекции |
| visit_person_ids | Настоящий код человека для каждого визита из независимой разметки. Один постоянный код на человека, в том числе незарегистрированного |
| probes | Эмбеддинги кадров визитов, F × 512, та же модель и подготовка, что у enrollment |
| frame_visit_ids | Код визита каждой из F строк |
| frame_numbers | Неотрицательный номер кадра внутри визита. Пара «визит, номер» уникальна |

Коды людей в обоих массивах должны принадлежать одному пространству. Зарегистрированный получает одинаковый код при зачислении и в разметке. Используйте строковые массивы NumPy или целые числа одинаковой знаковости. Не используйте объектные массивы.

Номера кадров задают последовательность наблюдений, на которых система должна принять решение. При намеренном прореживании потока нумеруйте запланированные наблюдения по порядку, сохраняя пропуски при потере кадра или отсутствии лица. Для визита совсем без детекций достаточно строки в реестре визитов. Если в сцене несколько лиц, заранее сопоставьте наблюдения с проходящим человеком независимо от предсказанного ID.

### Запуск

Из корня проекта. Значения порогов ниже иллюстрируют синтаксис. Для рабочего отчёта подставьте действующие пороги или значения, выбранные на отдельной калибровочной выборке.

```sh
PYTHONPATH=python python training/scripts/eval_gate_visits.py visits.npz \
  --min-score 0.80 --min-margin 0.05 --confirmations 1 2
```

При двух подтверждениях требуются два соседних наблюдения с одним и тем же принятым ID. Пропуск номера, другой ID или отказ начинает серию заново. Кадры сортируются внутри визита. При единственном подтверждении ошибочная первая выдача остаётся ошибкой, даже если на следующем кадре система узнала человека правильно.

В отчёте `false_identifications` — визиты посторонних, которым выдан зарегистрированный ID. Среди зарегистрированных `known_misidentified` считает выдачу чужого ID, `known_rejected` — отказ, `correct_identifications` — правильный ID. FPIR делится на число визитов посторонних, FNIR — сумма ошибочных выдач и отказов своим, делённая на число визитов своих. Макросредние сначала вычисляются внутри каждого человека.

### Контрольный сценарий

В тесте семь искусственных визитов: четыре своих и три посторонних. Порог и последовательность кадров одинаковы для обоих режимов. Один свой не дал ни одного пригодного кадра; один посторонний дважды подряд совпал с тем же чужим шаблоном.

| Исход | Один кадр | Два подряд |
|---|---:|---:|
| Постороннему выдан ID | 2 из 3 | 1 из 3 |
| Своему выдан чужой ID | 1 из 4 | 0 из 4 |
| Своему отказано | 1 из 4 | 2 из 4 |
| Свой правильно распознан | 2 из 4 | 2 из 4 |

Сценарий проверяет логику подсчёта и цену повторного подтверждения. Для оценки качества нужна размеченная выборка визитов с конкретной проходной. Запуск сравнивает политики офлайн, состав галереи и пороги одинаковы.
